# Documentation map

## Active — mirrored into Obsidian

- [Current operation](active/current-operation/README.md): how the implemented application works.
- [Setup and maintenance](active/setup-and-maintenance/README.md): install, configure, run and maintain it.

Only `docs/active/` is mirrored under Self documentation in the private vault.
The model remains disconnected from vault browsing and direct file editing.

## Development — outside Obsidian

Start with the [Development index](development/README.md).

- [Experiments](development/experiments/README.md): recorded tests and investigations, not current configuration.
- [Reports extracted from Active guides](development/experiments/active-guide-reports-2026-11-12/README.md): prior verification runs and rollout notes.
- [History](development/history/README.md): baselines and retired documents.
- [Ideas](development/ideas/README.md): discussion-only proposals; saving an idea does not authorize implementation.

The active guides may cite development evidence, but those cited files are not
copied into the vault. See [the saved baseline](development/history/baseline.md)
for recovery to the historical checkpoint, not the current code's behavior.

Keep current instructions, supported migrations and known limitations in Active. Put dated test outcomes and measurements in Experiments, retired descriptions and audits in History, and unapproved proposals in Ideas. Maintenance commands may stay in Active; their recorded results belong in Development.
